# ReAct 执行循环

ottercode 0.3 使用显式 ReAct 循环。此前版本已具备模型选择工具、工具结果回填、再调用模型的循环，本次增加明确的决策约定、状态转换约束、阶段事件与持久化。

ReAct 的核心是让决策和环境交互交替进行，依据观察调整后续行动。参考 [ReAct 原项目与论文](https://react-lm.github.io/)。本项目通过结构化 function calling 表达行动，保留模型服务的原生消息格式。

## 一轮如何运行

```text
用户目标 + 项目指令 + 历史观察
                 │
                 ▼
         Reason：模型评估下一步
           │                 │
       工具调用           最终答复
           ▼                 ▼
         Act               Finish
     Hook → 校验 → 审批
           │
           ▼
    实际工具结果写入 tool 消息
           │
           ▼
        Observe ──────────→ 下一轮 Reason
```

- **Reason**：系统提示要求模型结合目标和已有观察作出决定；需要操作时给出简短行动目的与待验证事项。使用已有的一次模型调用，不额外增加“思考调用”。界面中的 Reason 仅表示等待模型决策的执行阶段，不代表模型输出了思维链。
- **Act**：只执行完整且符合协议的结构化调用。Hook、参数校验、目录指令与权限审批仍然适用；`action` 阶段包含这些执行前检查，不等于操作已经获批。
- **Observe**：工具状态与内容落盘为原生 `role: tool` 消息，按调用 ID 配对，下一轮模型请求能看到实际结果。成功、失败、拒绝、取消均属于观察；不得把意图当作执行结果。
- **Finish**：模型没有工具调用时给出最终答复；取消、预算耗尽、输出截断、协议错误和 Hook 终止也有对应结束原因。正常完成只表示模型结束任务，不证明测试通过。

优先每轮一个行动；依赖前一结果的行动必须等待下一轮。为兼容模型一次返回多个工具，保留串行批处理，轨迹为 `Reason → (Act → Observe)* → Reason`。批中观察先后落盘，批结束后才重新调用模型；实现不声称在批内重新规划。

模型行动说明使用已有 assistant 文本，不要求供应商返回隐藏推理字段，也不解析文本中的 `Thought:` 或 `Action:` 执行工具。工具调用不会因为缺少行动说明而被拒绝，兼容只返回 function calling 的模型；系统提示不能强制保证模型实际遵守所有规划约定。

## 状态、事件和恢复

`ReActLoop` 校验状态转换：行动必须在决策或前一个观察之后，观察必须匹配当前调用，未观察的行动不能进入下一轮决策。每次用户任务有独立 `runId`，`step` 从 1 开始，按模型决策轮次递增；压缩调用不计入步骤，但照常占用模型预算。

`AgentEvent` 增加 `react_step`，载荷为 `ReActState`：

```json
{"type":"react_step","state":{"runId":"<UUID>","step":2,"phase":"observation","toolCallId":"read_2","toolName":"read_file","status":"success"}}
```

事件不重复携带工具全文或私有推理。详细内容从已有 `text`、`tool_start`、`tool_end` 与会话消息读取。阶段先写入 JSONL 和快照，再发出事件；Observe 出现在对应 tool 消息持久化之后。存储失败会停止任务，已经产生的外部副作用不能回滚。

交互终端显示如 `ReAct #2 · 评估下一步`，非交互终端写入 stderr，例如 `[react:2] observation`。SSE 透传阶段事件，`WorkspaceSnapshot.task.react` 携带当前阶段；事件被淘汰或连接中断后通过快照恢复显示，无需重放工具。

会话快照的可选 `react` 字段保存最新阶段，旧会话继续兼容。恢复时将未结束的阶段标记为 `finish/cancelled`，并沿用工具消息配对修复机制；不会恢复执行。新任务产生新 `runId`。上下文压缩仅替换活动消息，保留独立 JSONL 轨迹；子 Agent 使用各自独立轨迹，原有根任务共享预算与费用归集逻辑不变。

## 验证

`test/react.test.ts` 覆盖转换约束、真实失败观察驱动下一步、Hook 拒绝、批量串行配对、各类结束路径、中断恢复和审批期间快照。已有 CLI 端到端测试继续真实运行搜索、读取、修改、验证、汇报，并检查阶段日志；终端测试检查阶段显示，断线测试检查待审批阶段恢复，子 Agent 测试检查独立运行 ID。

可用于简历的表述：

> 基于 ReAct 构建编程 Agent 执行循环，将模型决策、工具行动与真实观察映射为显式状态流，结合 Hook 审批、SSE 状态同步和 JSONL 持久化，实现可追踪、可取消的多轮工具执行。
